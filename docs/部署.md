# 部署 · CI/CD → 云端（AWS ECS Express Mode）

`git push master` → 全自动测试、构建、推镜像、部署上云。本文记录架构、AWS 资源、流程与踩过的坑。

## 流水线（一张图）
```
git push master
   │
   ├─ test            pytest（离线、不打 Grok、无需任何密钥）
   ├─ build-and-push  OIDC assume 角色 → docker build → 推 ECR（tag: latest + git-sha）
   └─ deploy          OIDC → aws-actions/amazon-ecs-deploy-express-service
                      → 创建/更新 ECS Express 服务（Fargate + ALB + HTTPS URL）
PR / 其他分支：只跑 test（CD 只从 master）
```
定义在 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)。架构模式 = **Registry 驱动**：Actions 负责 CI + 构建 + 推 ECR；ECS 负责跑。

## 关键设计：无长期密钥（GitHub OIDC）
CI 不存任何 AWS access key。每次跑时，GitHub 签发短命 OIDC token，向 AWS **临时 assume 一个 IAM 角色**换取临时凭证。
> 面试一句话：*"CI assumes an IAM role via OIDC for short-lived creds — no static AWS keys in GitHub."*

## AWS 资源清单（account <AWS_ACCOUNT_ID> / region ap-northeast-1）
| 资源 | 名称/标识 | 作用 |
|---|---|---|
| ECR 私有仓库 | `torisu233/trpg` | 存 Docker 镜像 |
| OIDC provider | `token.actions.githubusercontent.com` | 让 AWS 信任 GitHub Actions |
| CI 角色 | `github-actions-deploy-role` | GitHub 经 OIDC assume；信任 `repo:torisu233/*` |
| └ 托管策略 | `AmazonEC2ContainerRegistryPowerUser` | 推 ECR |
| └ inline 策略 | `ecs-express-deploy` | 12 个 `ecs:*` 部署动作 + `iam:PassRole`（仅限下面两角色、仅交给 ecs） |
| ECS 执行角色 | `ecsTaskExecutionRole`（service-role 路径） | ECS 拉镜像 + 写日志 |
| ECS 基础设施角色 | `ecsInfrastructureRoleForExpressServices` | Express 代建 ALB/网络 |
| ECS Express 服务 | `trpg`（cluster `default`） | 跑容器、给公网 HTTPS URL |

## 密钥处理（路线一：env 变量，刻意不上 Secrets Manager）
- `GROK_API_KEY`、`APP_PASSWORD` 存为 **GitHub repo secrets** → deploy 时经 action 的 `environment-variables` 注入容器环境变量。
- **不用 AWS Secrets Manager**：设计仍在演进，换 key 只改 GitHub secret、不碰 AWS——保留灵活，接受「key 明文存在 task definition（自己帐号内可见）」的代价。
- 官方确认：用 `environment-variables`（明文 env）**无需** execution role 任何 Secrets Manager 权限（只有 `secrets`/`valueFrom` 才需要）。
- 架构观：**对外 = auth 登入（待做），对内 = AI key 等服务器端密钥**，key 永不进前端、不进 repo、不进镜像。
- `APP_PASSWORD` 是**临时公网闸**，上了用户 auth（见末尾）即移除。

## 容器为 ECS 准备的要点（Dockerfile）
- 监听 `0.0.0.0`、端口用 `${PORT:-8080}`；**非 root** 运行。
- **坑：ECS Express 容器端口默认 80**，必须设 `container-port: 8080`——否则 ALB 健康检查打 80、容器在 8080 → unhealthy。且**非 root 绑不了 80**（特权端口），所以是「让 ECS 对齐 8080」，不是改 app。
- 健康检查路径 `/api/health`（免密码、极轻、不依赖前端）。
- CMD 用 exec 形式让 uvicorn 正确收 SIGTERM（关闭干净）。

## 怎么部署 / 触发
- **自动**：push 到 `master` → CI 三段跑完即上云更新。
- 部署后取 URL：`deploy` job 日志，或 ECS 控制台 → `default` → 服务 `trpg` → 端点。
- 验证：`/`（简体 SPA，有 `APP_PASSWORD` 先登入）、`/api/health` → `{"ok":true}`、实际玩一局（需 `GROK_API_KEY` 已注入）。

## 成本 / 拆除（重要）
ECS Express = Fargate + ALB，**跑着就计费**（ALB 有基础时薪）。Demo 用法：部署 → 截图/录影 → **Delete 服务**（ECS → `default` → `trpg` → Delete，连带清 ALB）。要再验证：push 一次即自动重建。已设 budget 告警双保险。

## 踩过的坑（备查）
- **App Runner 自 2026-04-30 起不收新客户** → 改用 **ECS Express Mode**（官方替代，吃 ECR 镜像）。
- 容器端口默认 80 vs app 8080（见上）。
- IAM 部署权限：action 实际需 12 个 `ecs` 动作（含 `ListServiceDeployments`/`DescribeServiceDeployments`/`TagResource`/`UntagResource`，用于查部署进度+打标签）；少了会在「等部署完成」处 AccessDenied。`iam:PassRole` 须显式授权且用 `iam:PassedToService=ecs.amazonaws.com` 收紧。

## 已知不足 / 下一步
- **数据持久化**：Fargate 文件系统**临时 + 不跨 task 共享** → 现在的 JSON 档存储（`scenarios/`、`data/games/`）在云上**重部署即丢、多实例不共享**。需迁移到**数据库（PostgreSQL + SQLAlchemy，云端 RDS）**——这也是用户 auth 的地基。
- **auth 登入**：用真用户账号（注册/登录 + JWT）替换共享 `APP_PASSWORD`，每用户各自的游戏。
