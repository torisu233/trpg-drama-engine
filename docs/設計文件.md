# 多 Agent 跑團式互動遊戲 — 設計文件

## 一、概述

打造一個類似跑團（TRPG）的互動遊戲。由多個 AI agent 分別扮演不同角色（隊友、敵人），真人玩家扮演一個角色加入我方，與隊友協作對抗敵人，進行多輪互動。互動不限於戰鬥——對話、談判、戰鬥等皆走同一套迴圈。整體體感應接近「一本正在被共同書寫的小說」。

系統的四個核心要素：

1. **行動意圖** — 每個角色（含玩家）表達「這一拍想做什麼」。
2. **意圖裁決** — 一個中立機制裁決意圖是否實現、實現到什麼程度，並決定「誰察覺到了這件事」。
3. **互動結果描述** — 每次互動的結果被寫成貼著視角的散文回饋給對應對象。
4. **行動次序流** — 用「行動條」推進節奏，把上述三件事串起來。

## 二、設計取向（核心前提）

本專案明確選擇 **「氣氛優先、快速原型、不追求機制公平」** 的路線。

傳統跑團用骰子與數值製造「逆境與不確定」，本專案刻意**不靠骰子與血量數據決定成敗**，而用**戲劇引擎**取代**機率引擎**——靠對抗、靠戲劇張力製造緊張與意外。

更進一步：本作不依賴數值來模擬局勢，而是以**狀態與情景**作為骨架。「一個被綁起來的敵人無法戰鬥」「一個喝醉的敵人更難命中」「一個背靠牆的敵人無法被背後偷襲」——這些用數值模擬很笨重，但對 LLM 而言是自然的推理。因此局勢的骨架是一份**離散的狀態事實清單（狀態帳本）**，由裁決 agent 仔細推理、據以裁決。

對應的替代引擎：

- 一個真正難纏的**敵人 agent**，作為不確定性的來源
- 用「**結果階梯**」取代命中判定
- 追蹤質性的「**狀態帳本**」而非血量數值
- 一點**運氣神諭**作為調味（見第九節）

> 數值只出現在一個地方：**行動條的排程**（決定誰先動）。它是「排程數字」，從不決定成敗，因此不違背上述哲學。

## 三、角色與 Agent 分工

設計刻意把職責分權，避免任何單一 agent 同時掌握「知道一切」與「裁決一切」的權力。

| 角色 | 由誰擔任 | 職責 | 看得到的資訊 |
|------|---------|------|------------|
| 敵人 | 獨立的持久 LLM 對話 | 扮演狡猾、難纏的對手，盡力威脅我方 | 只看得到敵方當下**能感知**的局面（動態迷霧） |
| 隊友 | 獨立的持久 LLM 對話 | 與玩家同陣營協作，共享陣營計策 | 我方公開資訊 + 陣營私有計策 |
| 玩家 | 真人 | 透過輸入扮演我方一個角色，可用隱蔽手段傳意圖 | 我方資訊 + 自己感知到的局面 |
| GM／敘事者 | 中立 LLM（與角色分開） | 把裁決結果寫成貼著視角的散文，**逐對象分發不同版本** | 拿到「地面真相」與感知分發表作為輸入，不偏袒任一方 |
| 流程控制器＋裁決器 | 程式 + 中立裁決 agent | 推進行動條、裁決意圖、維護權威狀態、決定誰知道什麼 | 全知，但只執行規則、不帶立場 |

設計重點：

- **敵人是獨立 agent，而非由 GM 一手包辦。** 理由不是公平，而是對抗品質——一個試圖把全場做圓的 GM 會不自覺手下留情；一個只被告知「你要贏、你要威脅對方」的敵人 agent，才會給出真正讓玩家難受的招。
- **角色 LLM 維持持久對話**（而非每拍重生的臨時 subagent），以累積這場仗的記憶。
- **排序權、扮演權、裁決權三權分立**：決定順序與裁決結果的必須是中立方，不能兼任任一角色。
- **角色 agent 永遠不能直接改狀態帳本**，只能「表達意圖」或「放棄行動」。唯一能寫帳本的是裁決 agent。

## 四、編劇層：劇本生成

**階段一・編劇（離線，迭代式）**：你給粗胚（例如「在酒館和隊友遇到敵人」），編劇 agent 把它展開成可被裁決的結構，並**埋好玩家不知道的秘密**（戲劇張力的來源）。流程為 **AI 提案 → 你可改任一欄 → 定稿**。

劇本內容（要點是「初始狀態帳本 + 秘密 + 迷霧邊界」，而非單純場景描述）：

```
劇本 = {
  場景       : "雨夜酒館，爐火將熄，後門通向馬廄",
  角色卡     : [ …見第五節第一層… ],
  初始會變層 : { …見第五節第二層… },        // 姿勢/位置/物品/秘密的起始值
  迷霧與秘密 : {
     "刀疤怕火"           : 可見性 gm,        // 玩家/隊友不知道
     "刀疤在等同夥包抄"   : 可見性 gm
  },
  軟目標     : "活著問出刀疤的雇主是誰"      // 可選；見第十二節「結束」
}
```

### 實作：編劇 agent（對話式區塊編輯，共享劇本文件）

劇本＝可序列化的 `Scenario`（世界觀＋scene＋角色卡＋初始會變層，存 `scenarios/*.json`）。兩種編輯途徑共用**同一份劇本正本**：

- **手動**：直接編輯各區塊（前端表單）。
- **對話**：`author_turn(當前劇本, 對話史, 使用者訊息) → AuthorReply`——agent **對劇本無狀態**，每回合收到當前完整劇本、**只更新一個區塊**（world / scene / char / ledger / none）＋一句回覆；程式把區塊**以「空欄＝不更動」逐欄合併**回正本（ledger 角色用 key 級合併），**防 agent 誤清既有內容**。

「無狀態＋共享正本」＝前端持有草稿、agent 永遠看到最新（含使用者手動改的），存檔才落地。agent 內建編劇守則：雙用角色卡、**弱點設 gm 秘密**、世界觀法則影響裁決、埋鉤子、設先機（初始行動值）、**陣營只用「我方/敵」**、能力弱點用質性描述。

**刪除分工（刻意）**：因「空欄＝不更動」，agent 能做**改值/新增/欄內刪一項**（回傳變短的非空清單）；但**整張角色卡刪除、整欄清空**留給使用者在面板手動完成——破壞性操作手動更明確，也避免 agent 誤刪。

CLI：`python -m backend.author`；前端到位後同一套核心接對話框＋可編輯面板即可。

## 五、狀態模型：世界觀（靜態）＋ 兩層帳本

治理「狀態很多」的核心手法是**把「幾乎不變的」與「每拍會變的」徹底分開**，只有後者進入每拍重注入 + delta 的循環；並把會變層**按主體分組成巢狀視圖**，讓 agent 低負擔取用。

「不變的」其實有兩塊：**世界觀**（全局）與**角色卡**（個體）——兩者都是裁決的靜態依據，每拍重注入但不進 delta。

### 靜態・世界觀（全局法則，存劇本）

不只是氛圍文字，更含**影響裁決的硬規則**：

```
世界觀 = {
  基調 : "武俠。江湖恩怨、刀光劍影",                // 給 GM 語氣
  背景 : "漕幫把持運河…約 200 字設定",             // 給所有 agent 接地
  法則 : [                                         // ★ 裁決必須遵守的硬規則
    "武功大成者運氣護體，尋常刀劍難傷要害，須以內力/毒/火/點穴/攻其弱點/斷其根基方能制之",
    "輕功高者可飛簷走壁、瞬間欺近或脫身",
    "內傷重於外傷，且難以速癒"
  ]
}
```
- `基調`→GM 語氣；`背景`→所有 agent 接地；**`法則`→注入裁決，作為可行性的硬約束**（例如對護體高手用尋常刀劍，判為無效或大打折扣）。

### 靜態・角色卡（個體，存劇本，極少改）

**雙用欄位**：一半給角色 agent 演戲，一半給裁決判定。**關鍵：角色卡不會被注入給對手**，因此「裁決用」的固有特質（防禦/弱點）天然只有「裁決＋本人」知道，是**可被遊戲中發現利用的秘密**：

```
char_scar = {
  名:"刀疤", 陣營:"敵",
  性別:"男",                                        // ★ 可觀察的基本資訊（性別/外貌/年齡）→ 列入視圖與名冊，公開可見，避免被腦補弄錯
  ── 演戲用（角色 agent 與本人讀；對手看不到）──
  身分背景 : "漕幫打手…",
  性格     : ["狡猾","記仇","欺軟怕硬"],
  說話風格 : "皮笑肉不笑、愛拋狠話又留餘地",        // 讓對話有辨識度
  動機目標 : "拖到同夥包抄再一舉拿下",              // 驅動其選擇
  行為偏好 : ["能拖就拖","占上風才動手"],           // 慣用手段
  ── 裁決用（裁決全見；對手看不到，可為秘密）──
  能力     : ["漕幫快刀，近身狠辣"],
  防禦特性 : ["橫練護體，尋常拳腳難傷"],            // 影響裁決：難傷
  弱點     : ["怕火（秘密）","貪功怕死"]            // 影響裁決：攻其弱點效果顯著
}
```
> 「固有特質放卡裡 → 裁決全見、本人自知、對手看不到」——所以「怕火」這類秘密弱點能被玩家在遊戲中發現並利用，而非開局攤牌。**已取得/外顯**的狀態（如當場被斷一臂）才放會變層。

### 第二層・會變層（物品 + 各種狀態，唯一由裁決 delta 修改）

按主體分組。每個角色一個整潔區塊；另有場景區塊與陣營私有區塊：

```
會變層 = {
  角色: {
    char_scar: {
      姿勢位置 : "背靠吧台站立",
      身心狀況 : ["右肋重傷", "起疑"],          // 含會改變行為的心理狀態
      特殊情況 : [],                            // 被綁/被囚/昏迷等高影響狀態
      物品     : { item_knife: {狀態:"完好", 位置:"右手"} },
      ── 衍生欄位（裁決順手更新，供程式/agent 直接使用）──
      行動速度 : "慢",                          // 由負傷推導 → 餵行動條
      感知能力 : "受限：分心，背後易疏忽"        // 由重傷推導 → 餵感知分發
    },
    char_player: { … }
  },
  場景: {
    空間關係 : ["刀疤背靠吧台 → 防背後偷襲、退路受限"],   // 關係/位置事實
    場景事實 : ["後門上鎖", "爐火將熄"],                  // 環境 + 已揭露情報（用可見性控制誰知道）
    社會事實 : ["刀疤答應談判期間不動手 → 毀約有代價"]     // ★ 承諾/協議/結盟/招供，帶 gates 與可見性
  },
  陣營私有: {
    我方: { 計策: ["阿青引開、玩家繞後"] }       // 分發給敵人時整塊濾掉
  }
}
```

**單一狀態條目的通用結構：**

```
狀態條目 = {
  內容    : 自然語言事實,
  gates   : "這如何約束後續行動",   // 裁決「創建時」寫好，之後優先讀它（快取推理、防漂移）
  程度    : 可選，只在會惡化時給質性階（微醺/醉/爛醉、輕傷/重傷/瀕死）,
  可見性  : public | faction:陣營 | self:角色id | gm,
  來源    : 哪一拍哪個行動造成,
  生命週期: 何時失效/解除,
  剩餘拍數: None=持久；整數=N 拍後自動過期（瞬態，見第五節末「長場景維護」）
}
```

**物品**置於會變層（可消耗、可破損），但保留「身分穩定 / 狀態可變」拆分以防名稱漂移：

```
item_knife = {
  ── 穩定 ── 名:"生鏽短刀", 類型:"武器", 固有性質:["刃鈍","易斷"],
  ── 可變 ── 狀態:"完好→缺口→折斷", 位置:"右手→落地", 數量:(消耗品才有)
}
```

### 低負擔三原則

1. **巢狀分組**：agent 不讀全域大清單，只讀「它能感知到的、已整理好的視圖」。
2. **衍生欄位快取**：`行動速度`、`感知能力` 由裁決順手算好，行動條迴圈與感知分發直接取用，不必每次重推。
3. **穩定欄 vs 可變欄分明**：裁決只准動可變欄；設定與固有性質永不被誤改。

### 社會/資訊事實的歸屬（多輪對話的記憶關鍵）

帳本即長期記憶——**帳本是全量注入、不截斷的**（敘事散文流才用滑動窗）。所以「該記住的事」要進帳本，而非只留在會被截斷的散文裡。對話/談判產出的東西分三類歸屬：

- **承諾/協議/結盟/停火/招供 → 新增 `社會事實` 欄**（場景層），帶 `gates`（毀約/破壞的後果）與可見性。
- **已揭露情報（誰知道了什麼）→ 複用 `場景事實` + 可見性**，不另設欄位（可見性本來就 = 誰知道）。
- **對人態度（起疑/動搖/信任）→ 留在 `身心狀況`**（它就是心理狀態），不另設欄位避免膨脹。

這樣 10 輪對話後，第 1 輪的招供/承諾仍在帳本裡有效，且 fog 由可見性自動正確。

### 長場景維護：滾動摘要（文氣）＋ 瞬態 TTL（清理）

兩個「每拍結束」的自動維護步驟，讓場景拉長也不爆 context、不堆積：

- **滾動摘要（管文氣）**：角色記憶 = `摘要（壓縮的舊事）＋ 最近 W 拍逐字`（W=5）。某角色記憶達 2W=10 條時，把最舊 W 條交摘要器**合併重壓**進滾動摘要（per-character，迷霧忠實）。摘要**只記故事感/關係/情緒/張力，不記精確狀態**（狀態在帳本）。只摘要 AI 角色（玩家是真人、自讀公開日誌）。
- **瞬態 TTL（管清理）**：`剩餘拍數`（None=持久；整數=N 拍後消失）。裁決為短暫狀態（姿勢晃動/被驚嚇/火光蔓延）設 1–3 拍，持久狀態（傷勢/承諾/情緒轉變）留 null；程式每拍按 `回合數 − 創建回合 ≥ 剩餘拍數` 自動修剪。
- **重複累積的根治（已實作「帳本整理 pass」）**：TTL 只清「過期瞬態」；「升級不刪舊」造成的近義重複（同一條招供被反覆新增）由**帳本整理 pass** 根治：每拍結束後，若某清單的「**公開且持久**」條目達門檻（預設 4），呼叫 LLM 合併近義、清冗餘；**gm／self／faction／帶 TTL 的瞬態一律不動**（保護迷霧與 TTL）。自我調節——合併後縮短，再累積到門檻才觸發。裁決紀律（升級即刪舊）作為輔助。

## 六、行動次序流：行動條

取代死板的輪流。每個角色有一條行動條，按「行動速度」累積；達到**門檻（20）**即可行動，行動後**扣掉門檻、保留溢出**（公平且平滑）。速度由**當下狀態即時推導**，反映虛構。

```
loop:
  各角色 += 行動速度                          // 每發生一次行動，全場累積一次
  while 沒人達門檻:  各角色 += 行動速度        // 沒人能動就再加，直到有人達標
  actor = 達門檻者中行動值最高者
          （平手：玩家優先 → 否則值高者 → 再否則固定序 快>常>慢）
  actor 行動（玩家→暫停等輸入；NPC→agent 出意圖）
  → 兩軸判定 → 裁決 → 敘事 → 分發
  actor.行動值 -= 門檻                         // 保留溢出，不歸零
```

> **為何保留溢出、不歸零**：只要每次扣門檻保留溢出，長期下來「行動次數比 = 速度比」，比例乾淨可預測；歸零會丟失溢出、扭曲比例。這條是整個機制公平的關鍵。

速度值（基礎收緊在 4–7，避免次序拉太開；極端狀態才破格往下）：

| 當前狀態 | 速度 | 長期行動佔比 | 相對玩家 |
|---|---|---|---|
| 玩家（預設略高） | 7 | 32% | 1.0× |
| 快（靈活戒備） | 6 | 27% | 0.86× |
| 常（普通） | 5 | 23% | 0.71× |
| 慢（負傷／酒醉／笨重） | 4 | 18% | 0.57× |
| 重傷 | 3 | — | 破格 |
| 瀕死／被壓制 | 2 | — | 破格 |
| 昏迷／重縛 | ≈0 | — | 自然排不進來 |

設計效果：

- **次序不拉太開**：正常區間 4–7，最慢者仍有玩家 57% 的出手率，沒人被晾在一邊；玩家又明顯最活躍。
- **重度狀態才真的拖慢**：日常變化收緊，但重傷/瀕死破格往下，受創確實降低節奏。
- **昏迷者速度≈0，行動條永不滿，自然輪不到他**——以結構取代「強制跳過」。萬一仍排到，agent 也清楚自己昏著，演成「動彈不得」。**不設硬性跳過旗標，讓 agent 自行理解狀態。**
- **速度隨虛構即時變化**：速度從會變層的 `行動速度` 衍生欄讀取，一旦被打成重傷，下一個 tick 就立刻變慢。行動經濟自動跟著局勢走。
- **先機由初始值播種**：全員從 0 起跳則玩家必先手；要做突襲/埋伏，讓劇本把偷襲者的初始行動值設高（例如起手 15），即可讓敵人搶到開場。先機用「初始值」表達，不去動基礎速度。
- **可選旋鈕**：行動「成本」可變——拚命的重擊扣較多值（下次更晚輪到），輕巧動作扣較少。給戰術質感，仍不碰成敗數值。

## 七、裁決 agent：行為與知識的中樞

裁決 agent 是整個系統的權威核心，肩負**兩項並重的職責**：

- **行為管理**：判斷意圖在當前狀態下是否可行、實現到何種程度，並把結果寫成對狀態帳本的增刪改（delta）。
- **知識管理**：決定這件事**誰察覺到、察覺到多少**，產出一張感知分發表，據此維持並動態調整迷霧。

兩者都必須中立、可審計，因此用 **structured output 逼出一條可檢查的推理鏈**，避免它偷懶、漏看狀態、或被角色的話術說服（例如敵人 agent 在意圖裡夾帶「我早就掙脫了繩子」——裁決必須以帳本為唯一真相來源，駁回未經裁決的既成事實）。

### 強制思考協議（裁決的雙輸出）

```
裁決輸入：本拍行動意圖（+ 對方反應意圖，若有收集）
        + 世界觀法則 + 完整狀態帳本（地面真相，含各角色固有特質：能力/防禦/弱點）
        + 運氣神諭結果（若為爭議）

裁決輸出（強制格式）：

A. 行為裁決
  1. relevant_conditions : ["char_scar.特殊情況: 雙手被反綁", "場景.空間關係: 背靠吧台"]
        └ 逼它列出它「看到」哪些相關狀態，不准無視
  2. per_condition_judgment :
        雙手被反綁 → "阻止"（無法持械攻擊）
        背靠吧台   → "改寫"（背後無空間可繞）
  3. feasibility   : 不可能 / 受阻 / 可行 / 需改寫
  4. ladder_choice : 成功 / 成功但有代價 / 局勢逆轉   （結果階梯，見第九節）
  5. ledger_delta  : { add:[…], remove:[…], modify:[…] }   // 唯一的權威狀態變更

B. 知識裁決
  6. 感知分發 : {
        char_scar(重傷分心) : "未察覺",                 // 注意不到背後動作
        char_boss           : "察覺：看到玩家移動",
        ally_阿青(隊友)     : "察覺＋懂暗號真意"
     }

C. 給 GM 的地面真相摘要（一句話）
```

這套協議達成：

- **第 1、2 步逼它看完所有相關狀態、世界觀法則與角色固有特質**——不准無視「被綁」就判攻擊成功，也不准無視「護體難傷」「怕火」這類法則/特質（對護體者用尋常刀劍須判無效或大打折扣；攻中弱點則效果顯著）。
- **第 5 步讓狀態變更顯式化**：局勢只能透過 delta 改變，不能在散文裡偷偷漂移。對話/談判的持久後果（招供/承諾/結盟/情報）也由 `ledger_delta` 記為「社會事實」，不只記物理狀態。
- **第 6 步把「誰知道什麼」收歸裁決**：唯有看得到全場狀態的裁決，才有資格判斷感知。迷霧因此能隨重傷、蒙眼、昏迷動態收窄。
- **整條鏈可被程式或一個輕量檢查審計**：若它判「攻擊成功」卻沒在第 2 步處理「被綁」，即為漏判。

## 八、行動的兩軸判定：反應與爭議

一個行動進入裁決前，程式先沿**兩條獨立的軸**做判定。兩軸常同時成立，但**不是同一件事**，務必分開處理：

| 軸 | 問題 | 決定什麼 |
|---|---|---|
| **A. 要不要收集反應？** | 對方需要先做出反應，再交裁決嗎？ | 是否多收一次「反應意圖」 |
| **B. 是不是爭議行為？** | 結果真的不確定嗎？ | 是否擲運氣神諭 |

對照：攻擊清醒的敵人＝兩者皆是；無人阻擋的後撤＝兩者皆否；被緊逼時後撤＝不收反應、但是爭議。

### 軸 A：對方要不要先反應？

**核心原則：只有當「結果取決於某個防禦者『當下、且他感知得到』的選擇」時，才收集反應。** 過三道閘門：

1. **對方感知得到嗎？** — 感知不到就無法反應。背後偷襲一個沒注意到你的敵人 → 不收反應，裁決直接當「突襲」處理。（呼應第十節：**你只能反應你察覺到的事**。）
2. **對方有能力做有意義的對抗嗎？** — 被綁、昏迷、失能者 → 無從反應，裁決直接判。
3. **對方是玩家嗎？** — 是的話**一定**給玩家反應。這就是「每一拍收在威脅上」的命脈：敵人攻過來 → 玩家必須回應，這一拍的鉤子自然成形。

> **時序與「寧可多收」**：反應在裁決*之前*收集，但「對方究竟感知到沒」要到裁決*之中*才定案。程式預判時用 `感知能力` 衍生欄粗篩，**模稜兩可一律收**；裁決事後若認定其實沒察覺，再把該反應裁定為無效。寧可多收、不可漏收。

**關鍵限制：反應是「意圖」，不是「判決」。** 防禦者可以表達「我要閃避」「我嘴上答應、心裡盤算反咬」，但**不能自行宣告成敗**。裁決拿 `行動意圖 × 反應意圖 × 狀態 × 運氣` 一起判，並參考防禦者的狀態與攻方手上的籌碼（例如握有把柄＝帳本裡一條狀態）才決定結果。否則被說服的敵人一句「我不為所動」就破功了。

> **反應是一種中斷（interrupt）**：防禦者為了防禦而反應，**不消耗他自己行動條的主動回合**（可選旋鈕：拚命的翻滾閃避才扣一點條）。所以「敵人出手 → 玩家被迫回應」不會打亂行動條經濟，反而是它的心跳。

### 軸 B：什麼是爭議行為？

- **非爭議（不擲運氣，直接裁決）**——結果由狀態預先決定：
  - 明顯可行：無人阻擋的後撤、撿起腳邊的刀。
  - 明顯不可能：被綁者揮拳、對昏迷者說服。
- **爭議（擲運氣神諭）**——結果真正不確定，通常因為：
  - (a) 對方能感知且能主動對抗（攻擊、說服清醒的敵人）；或
  - (b) **環境本身是賭注**（雨夜跳過屋頂裂縫、壓力下開鎖）——這類**沒有對手，但仍是爭議**。

### 走一遍範例

- **① 攻擊清醒的敵人**：軸 A 是（感知✓、能對抗✓）→ 收反應；軸 B 是 → 擲運氣。裁決判 `攻擊 × 防禦` 衝突。
- **② 說服敵人**：軸 A 是 → 收反應（但反應是「抗拒/動搖/假意順從」的*立場*，非判決）；軸 B 通常是。裁決看敵人的多疑/恐懼 + 攻方籌碼，常判「成功但有代價」。
- **③ 打鬥時後撤幾步**（兩種情況）：
  - **無人緊逼**：軸 A 否、軸 B 否 → 不收反應、不擲運氣，裁決只輕量更新 `姿勢位置`，一句帶過。
  - **被敵人緊逼**：軸 A **否**（後撤不針對敵人，敵人「要不要追」是他*自己回合*的主動決定），軸 B **是**（環境爭議，擲運氣）。裁決用結果階梯判代價：「成功但有代價」（拉開距離但露空檔被劃一刀）或「局勢逆轉」（被順勢逼向牆角）。

> 為何後撤*不*收敵人反應、而攻擊*要*？攻擊的結果**直接取決於**防禦者當下的閃/擋選擇；後撤的結果取決於**環境態勢**（相對位置、是否被緊逼），那是裁決讀帳本就能判的。敵人的「追擊」留到他行動條輪到時再主動做。

### 單拍兩軸流程

```
行動者意圖（攻擊/說服/後撤…）
   │
   ▼
[程式] 軸 A：對方該反應嗎？（感知✓ 能對抗✓ 或 是玩家）
        是 → 收集對方反應意圖（玩家則暫停等輸入）
        否 → 跳過（突襲 / 對失能者 / 無對象行動）
   │
   ▼
[程式] 軸 B：爭議行為嗎？  是 → 擲運氣神諭（隱藏）
   │
   ▼
[裁決] 判「行動意圖 ×（反應意圖）× 狀態 × 運氣」→ 結果階梯
        → ledger_delta ＋ 感知分發表
   │
   ▼
[GM] 逐對象敘事 → 分發
```

## 九、取代骰子的機制細節

### 1. 行動意圖

- 所有角色每拍只輸出**決策**，用結構化格式表達。原型採**三欄精簡**：`{ 行動:"掀翻桌子撞向刀疤", 目標:"刀疤", 隱蔽:false }`。
  - `行動`：一句話描述「想做什麼（**含具體做法**）」。原本設想拆成「行動類型 + 方式」兩欄，但實作發現玩家容易把兩欄寫成重複，且 LLM 看一句完整描述就懂——故合併為單欄；做法細節（攻哪裡/用什麼/利用環境/時機）直接寫在這句裡，才是改變裁決的關鍵。
  - `目標`：**主要對象**（char_id 或留空）——程式據此判軸 A 向誰收反應。它是「主要對象」，不是「唯一互動對象」。
  - `隱蔽`：是否想**瞞過敵人**（資訊維度，與「成不成功」的爭議維度無關）；true 時裁決做表象/真意拆分並判是否被識破。潛行/暗號/偷偷拔刀屬此。
- **有限複合**：一拍可含「一個主要動作 + 一個附帶小動作」（攻擊同時打暗號、後撤同時嘲諷），寫進同一句 `行動`。
  裁決逐部分判、權衡一心二用的代價（成功但有代價）；附帶對象（如收暗號的隊友）由感知分發處理、不另收反應。別貪多，一兩件即可。
- 意圖只說「想做什麼」，**絕不自行宣告成敗**。扮演敵人的 LLM 不可以說「我砍中了」——裁決權不在角色手上。

### 2. 結果階梯（取代命中判定）

裁決時不擲骰，而是從階梯挑一個**最有戲、且在已建立虛構裡最合理**的結果：

- **成功**
- **成功但有代價**
- **局勢逆轉**

挑選依據是戲劇性與合理性。關鍵原則：**很少給乾淨的成功**——多數動作回饋的是「你做到了，但……」，那個「但」就是讓場面繼續滾動的燃料。每個結果都以 `ledger_delta` 落地。

### 3. 敘事原則（寫進 GM 的 system prompt）

- **後果是質的、會改變能力的**：不寫「掉幾滴血」，而寫「右臂中刀後只能用左手」「武器斷了」。每個結果改寫下一步能做什麼。
- **每一拍收在威脅或選擇上**：保持「對打」而非「獨白」的命脈。
- **時間彈性**：無聊對峙一句帶過，關鍵一擊拆成慢動作；火力集中在那一個轉折點。
- **貼著視角寫**：寫角色的恐懼、判斷、痛感。
- **逐對象分發**：依感知分發表，給每個收件者寫各自版本的私密敘事。
- **準確歸屬**：嚴格按「行動者/對方回應/狀態變更」寫誰做了什麼、誰被影響，不可張冠李戴或改寫事件性質（如把「某人計謀被識破」寫成「某人無處藏身」）。
- **只寫本拍新發展**：敘事者會拿到「最近 1–2 拍的公開敘事」當故事進展——**承接它但不可復述**已寫過的事件或對白；本拍若只是繼續僵持，只寫這拍新增的細節。這是敘事品質的命脈（玩家看最多的就是敘事）。

### 4. 狀態帳本即局勢（取代血量）

第五節的會變層就是局勢的權威記錄。每次裁決更新它，並讓後續動作**受其約束**（受傷的手臂使不出重擊、背靠牆的人退無可退）。

### 5. 運氣神諭（每個爭議行動都擲）

在**爭議行動**（見第八節軸 B）上，程式擲一次粗的質性運氣（`霉運 / 平 / 好運`），作為**餵給裁決 agent 的偏置文字**，不是命中率：

- `霉運` → 裁決把結果階梯下調一階、或編一個倒楣的並發狀況（「刀在灑出的酒上打滑」）。
- `好運` → 容許罕見的乾淨成功，或一個意外的有利轉折。
- **怎麼倒楣／走運，由裁決在虛構裡決定**，保持劇情合理。
- 運氣**對角色 agent 隱藏**，只有裁決看得到，否則敵人 agent 會偷算。

非爭議的行動不擲，直接裁決。

## 十、知識與迷霧模型

**前提：單一場景、所有人同場行動。** 因此大多數物理動作是**全場可見（public）**，迷霧不是骨架而是例外。私密資訊只有三個來源：

1. **劇本預先準備的秘密**（`gm` 可見性）：弱點、隱藏意圖、暗藏物品——開場就藏好，靠劇情揭露。
2. **劇本指定單一陣營可發現**：避免每次都得為每個陣營裁決「誰發現了」；預設歸屬一個陣營。
3. **暗號（表象/真意）**：表象全場可見，但只有同陣營懂真意；別人看到了也不知道意思。

在這之上再疊一層**動態感知修正**（次要、例外）：蒙眼、昏迷、重傷分心的人，可能連全場公開的動作都漏看。

### 1. 表象與真意（由裁決拆分）

例如玩家桌下打手勢通知隊友——敵人看得到手動了（表象），但不懂意思（真意）：

```
玩家行動：桌下打手勢
  表象 : "玩家手指在桌沿動了動"      // 全場可見
  真意 : "示意阿青繞到刀疤背後"      // 只有我方懂
```

**角色 agent 只提供「意圖 + 想隱蔽的標記」；真正拆成表象/真意、並判定隱蔽是否成功，是裁決的知識管理職責。** 推論：**隱蔽可能失敗**——眼尖的刀疤可能讀穿你的手勢，這由裁決判定，不是自動成功。

### 2. 動態感知修正（例外層）

- 昏迷 → 什麼都收不到。
- 蒙眼 → 無視覺、有聽覺。
- 重傷分心 → 可能漏看別人的小動作。

接收者「收到什麼」由其 `感知能力` 衍生欄決定，裁決在感知分發表裡逐人判定（全部 / 部分 / 無）。這也直接決定第八節軸 A：**感知不到的人無法反應**。

### 3. 陣營私有與隱蔽協同

- 陣營計策是一條 `可見性 = faction:我方` 的狀態，多為劇本預設或私下商議產生；分發給敵人時整塊濾掉（敵人或許看到我方在低聲交談，但不知內容）。
- **「私下商議」動作**：玩家與隊友在敵人「不知內容」的通道對話，談定的計劃寫成 faction 計策。商議**不推進行動條**，產物由裁決 commit 進帳本。
- 隊友與玩家的資訊邊界：隊友看得到玩家的公開行動與陣營計策，但玩家的內心盤算未必餵給隊友 agent。

## 十一、角色職責契約與資訊邊界

把各角色的「做什麼 / 知道什麼 / 完成什麼」釘成實作契約：

| 角色 | 做什麼 | 知道什麼 | 完成什麼（產物） |
|---|---|---|---|
| 編劇 agent（離線） | 展開劇本、補全狀態、埋秘密、設初值 | 玩家粗胚 + 常識（全知造物） | 劇本檔：**世界觀（基調/背景/法則）**＋**雙用角色卡[]**（演戲欄＋裁決特質）＋初始會變層（含衍生欄、初始行動值、社會事實）＋迷霧秘密＋軟目標 |
| 流程控制器（程式，非 LLM） | 推行動條、兩軸預判、擲運氣、迷霧過濾分發、暫停等玩家、套用 delta、判結束、主持私下商議 | 全知，但只執行規則、不裁決 | 行動者、運氣值、各方視圖、暫停點、更新後帳本 |
| 角色 agent（敵/友） | 出行動意圖/反應意圖、可放棄、可發隱蔽意圖、私下商議 | 只有「感知分發允許＋自己記憶」；我方多看陣營計策 | 結構化意圖/反應，**絕不宣告成敗** |
| 裁決 agent | 行為裁決＋知識裁決、更新衍生欄、出 GM 摘要 | 完整地面真相＋意圖（＋反應）＋運氣 | 雙輸出：ledger_delta＋感知分發表＋GM 摘要 |
| GM／敘事 agent | 逐對象寫貼視角散文、收在威脅上、準確歸屬、只寫本拍新發展 | GM摘要＋感知分發表＋本拍行動者/回應/狀態變更＋最近敘事(故事進展)＋公開場面錨點 | 1 份公開敘事＋N 份私密敘事 |

### 已定案的六條邊界規則

1. **反應寧可多收**：軸 A 模稜兩可時一律收反應；裁決事後可裁定無效。寧可多收、不可漏收。
2. **表象/真意由裁決決定**：角色只標「想隱蔽」，裁決負責拆分並判定隱蔽是否成功（**可能被識破**）。
3. **初值由編劇設**：`行動速度`/`感知能力` 衍生欄與初始行動值，皆由劇本給定；之後由裁決維護、程式只讀快取。
4. **私密資訊的來源（單一場景前提）**：劇本預設秘密（`gm`）／劇本指定單一陣營可發現／暗號（看得到表象、不懂真意）／**角色卡固有特質（裁決＋本人知，對手看不到，可在遊戲中被發現利用）**。執行時極少動態裁決「誰發現」。
5. **GM 寫、程式送**：GM 只負責寫各版本散文，**由程式按感知分發路由進對應記憶**；維持迷霧邊界永遠是程式的責任。
6. **帳本永遠勝出**：角色記憶與權威帳本衝突時，以**裁決寫好的帳本**為準；每拍重注入該 agent 可見視圖即自動矯正漂移。

## 十二、輪次流程總圖

```
[編劇層] 編劇 agent ── 離線迭代產出劇本（初始帳本 + 秘密 + 迷霧）
        │
────────  以下即時迴圈，由行動條推進  ────────
        ▼
[程式] 行動條累積 → 選出本拍行動者（玩家優先）
        │
        ▼
[角色 LLM / 玩家] 產出行動意圖（只說想做什麼，可複合，可隱蔽）
        │
        ▼
[程式] 兩軸判定：
        軸 A 該收反應？ → 是則收集對方反應意圖（玩家則暫停等輸入）
        軸 B 是爭議？   → 是則擲運氣神諭（隱藏）
        │
        ▼
[裁決 agent] 強制思考協議：
        行為裁決（結果階梯 + ledger_delta）
        ＋ 知識裁決（感知分發表）        ← 行為與知識並重
        │
        ▼
[GM/敘事 LLM] 依感知分發，逐對象寫散文（收在威脅上）
        │
        ▼
[程式] 公開敘事給全體 / 私密結果回灌對應對話記憶（維持動態迷霧）
        │
        └──────→ 行動者行動條歸位，回到行動條累積
```

**「結束」如何判定**（小說式流程沒有 HP=0 的硬結局）：

- 劇本軟目標達成（問出雇主、活著離開）；或
- 玩家主動喊停；或
- 場面張力徹底消解、無未解威脅可繼續。

## 十三、實作備註

- **模式中立（prompt 不偏戰鬥）**：裁決/敘事/角色 agent 的 prompt 不寫死「威脅壓制」這類戰鬥指令；角色依**自己的動機目標**行事、手段隨情境。對話/交涉、偽裝/潛入皆走同一套（狀態＋結果階梯＋社會事實＋隱蔽感知），用該模式合適的**質性後果**——交涉記信任/讓步/把柄（社會事實）、潛入靠是否被識破（隱蔽感知），戰鬥才寫傷勢。敘事「收在未決張力上」（威脅/疑點/抉擇皆可，不限威脅）。
- **角色記憶**：敵人、隊友各自維護一條持久對話歷史，每拍往後接，記憶自然累積。迷霧邊界由程式劃定——分發局面時只給該方「感知分發表所允許」的資訊。
- **結構化一切**：意圖、反應意圖、裁決輸出（行為 delta + 感知分發）、狀態條目，全用 structured output 固定格式，方便程式解析與審計。
- **規則與裁決盡量寫在程式裡**（兩軸預判、合法性檢查、行動條推進、運氣擲點、迷霧過濾），**仔細推理的部分交給裁決 agent**（結果階梯選擇、狀態 delta、感知判定），**潤色交給 GM**。
- **真人輸入**：行動條每輪到玩家、或玩家被收集反應時，停下等輸入。這是保留薄程式框架的主因（自主 agent 的本能是一路跑完，需要被框住）。
- **裁決成本**：每個爭議拍可能涉及 行動意圖 + 反應意圖 + 裁決 + GM 多次 LLM 呼叫，是這條路線的固有代價。
- **複用 ai-word**：`ActionAnalyzer`（解析意圖）、`ReactionJudge`（反應收集，對應第八節軸 A）、`NarrativeGenerator`、`BattleEngine`（流程協調）可大量複用；`CombatCalculator` 的數值計算整個換成「裁決 agent + 狀態帳本」；`BattleState` 換成兩層狀態模型。新增的是持久角色 agent 對話與動態迷霧分發層。

## 十四、一句話總結

把「骰子＋數值」這套**機率引擎**，換成「對抗 agent ＋ 結果階梯 ＋ 狀態帳本」這套**戲劇引擎**：
**程式管「順序與框架」，裁決 agent 管「行為成敗與誰知道什麼」，角色 LLM 管「想做什麼」，GM 管「逐人講得好不好聽」。**
