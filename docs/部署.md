# 部署 · CI/CD → 云端（AWS ECS Express Mode）

`git push master` → 全自动测试、构建、推镜像、部署上云。本文记录架构、AWS 资源、流程与踩过的坑。

## 流水线（一张图）
```
git push master
   │
   ├─ test            pytest（连 CI 的 Postgres service container；不打 Grok）
   ├─ build-and-push  OIDC assume 角色 → docker build → 推 ECR（tag: latest + git-sha）
   └─ deploy          OIDC → aws-actions/amazon-ecs-deploy-express-service
                      → 创建/更新 ECS Express 服务（自建 VPC 公开子网 + app-SG）
                      → 容器启动先 alembic upgrade head 建表，再 uvicorn
PR / 其他分支：只跑 test（CD 只从 master）
```
定义在 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)。架构模式 = **Registry 驱动**：Actions 负责 CI + 构建 + 推 ECR；ECS 负责跑。

## 关键设计：无长期密钥（GitHub OIDC）
CI 不存任何 AWS access key。每次跑时，GitHub 签发短命 OIDC token，向 AWS **临时 assume 一个 IAM 角色**换取临时凭证。
> 面试一句话：*"CI assumes an IAM role via OIDC for short-lived creds — no static AWS keys in GitHub."*

## 密钥 / 配置（路线一：env 变量，刻意不上 Secrets Manager）
全部存为 **GitHub repo secrets**（仓库 `torisu233/trpg-drama-engine`）→ deploy 时经 action 注入：

| secret | 注入处 | 作用 |
|---|---|---|
| `LLM_API_KEY` | env | LLM(DeepSeek) 服务器端密钥 |
| `DATABASE_URL` | env | `postgresql+psycopg2://…@<RDS endpoint>:5432/trpg`（含库密码） |
| `JWT_SECRET` | env | 签发/校验 JWT（≥32 字节随机；`openssl rand -base64 48` 生成） |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | env | 空库首启 seed 初始管理员 |
| `APP_SUBNETS` | action `subnets` | 2 个公开子网 id（逗号分隔）；非机密，存 secret 只为不硬编码 |
| `APP_SG` | action `security-groups` | app 安全组 id |

- **不用 AWS Secrets Manager**：换 key 只改 GitHub secret、不碰 AWS——保留灵活，接受「值明文存在 task definition（自己账号内可见）」的代价。官方确认：用 `environment-variables`（明文 env）**无需** execution role 任何 Secrets Manager 权限。
- 架构观：**对外 = 用户 auth 登录（JWT），对内 = AI key / DB 密码等服务器端密钥**，永不进前端、不进 repo、不进镜像。
- 旧 `APP_PASSWORD` 公网闸**已被用户 auth 取代并删除**（中间件、config、env 与 publish 脚本均已移除）。

## 网络架构（Part 2：app 公开子网 / RDS 私有子网，同 VPC，免 NAT）
```
              Internet
                 │  [Internet Gateway]
 ┌───────────────┴──── VPC vpc-04ba…（DNS hostnames/resolution 开）──────────────┐
 │  公开子网 ×2 AZ                              私有子网 ×2 AZ                    │
 │  ┌──────────────────────────┐               ┌────────────────────────────┐  │
 │  │ Express: ALB + Fargate    │               │  RDS Postgres 16            │  │
 │  │ 任务有 public IP（拉 ECR/  │──5432────────▶│  publicly-accessible=否      │  │
 │  │ 连 LLM），挂 app-SG        │  app-SG  →    │  RDS-SG 入站只放行 app-SG    │  │
 │  └──────────────────────────┘  RDS-SG        └────────────────────────────┘  │
 └────────────────────────────────────────────────────────────────────────────┘
          无 NAT Gateway（出网的 app 在公开子网直连 IGW；RDS 不需出网）
```
- **指定子网**：action 传 `subnets`（2 公开子网）→ Express 建外网 ALB + 给任务 `assignPublicIP=true`。给私有子网才需自己配 NAT。
- **省 NAT ~$33/月**：要出网的是 app（在公开子网，直连 IGW）；要藏的是 RDS（私有子网，根本不出网）——两边都不需要 NAT。
- **SG 对 SG**：自建 `app-SG` 挂给任务（确定的 id，避开 Express 自建 SG 的先有鸡蛋问题），`RDS-SG` 入站 5432 仅来源 app-SG，RDS 不碰公网。
- **VPC 要求**：≥2 公开子网（Express ALB，跨 2 AZ）+ ≥2 私有子网（RDS 子网组要 ≥2 AZ）；`enableDnsHostnames`/`enableDnsSupport` 必须开。
- 面试一句话：*"App in public subnets with public IPs pulls ECR over the IGW — no NAT; RDS sits in private subnets, reachable only from the app's security group on 5432."*

## 数据库迁移（容器启动时）
- 容器 CMD = `alembic upgrade head && exec uvicorn …`：每次启动先把 schema 升到最新（**幂等**：空库建表、已最新跳过），再起服务。
- 第一次部署后线上自动就有：三张表 + seed 的 admin（来自 `ADMIN_*`）+ 示范剧本武侠001。
- Dockerfile 须 COPY `alembic.ini` + `alembic/`（否则容器内无迁移可跑）。
- 单任务（Express 默认 minTask=1）无并发迁移竞争；将来多任务需另设迁移闸/一次性 task。

## 容器为 ECS 准备的要点（Dockerfile）
- 监听 `0.0.0.0`、端口用 `${PORT:-8080}`；**非 root** 运行。
- **坑：ECS Express 容器端口默认 80**，必须设 `container-port: 8080`——否则 ALB 健康检查打 80、容器在 8080 → unhealthy。且**非 root 绑不了 80**（特权端口），所以是「让 ECS 对齐 8080」，不是改 app。
- 健康检查路径 `/api/health`（免密码、极轻、不依赖前端）。
- CMD 用 exec 形式让 uvicorn 正确收 SIGTERM（关闭干净）。

## 怎么部署 / 触发
- **自动**：push 到 `master` → CI 三段跑完即上云更新。
- 部署后取 URL：`deploy` job 日志，或 ECS 控制台 → `default` → 服务 `trpg` → 端点。
- 验证：`/`（简体 SPA，注册/登录后进）、`/api/health` → `{"ok":true}`、`/api/auth/register` 建号、实际玩一局（需 `LLM_API_KEY` 已注入）。

## 成本 / 拆除（重要）
- **ECS Express = Fargate + ALB，跑着就计费**。Demo 用法：部署 → 截图/录影 → **Delete 服务**（ECS → `default` → `trpg` → Delete，连带清 ALB）。要再验证：push 一次即自动重建。
- **RDS 独立计费**（db.t4g.micro 首年 free-tier；之后 ~$12–15/月 + 存储）。**删 ECS 服务不影响 RDS**——数据活在 RDS 里，所以重部署/重建服务数据都在。彻底不用了才删 RDS（`aws rds delete-db-instance --db-instance-identifier trpg-db --skip-final-snapshot --delete-automated-backups`）。
- **VPC/子网/SG 不计费**（NAT 才贵，我们没建）。
- 已设 budget 告警双保险。

## 踩过的坑（备查）
- **App Runner 自 2026-04-30 起不收新客户** → 改用 **ECS Express Mode**（官方替代，吃 ECR 镜像）。
- 容器端口默认 80 vs app 8080（见上）。
- IAM 部署权限：action 实际需 12 个 `ecs` 动作（含 `ListServiceDeployments`/`DescribeServiceDeployments`/`TagResource`/`UntagResource`，用于查部署进度+打标签）；少了会在「等部署完成」处 AccessDenied。`iam:PassRole` 须显式授权且用 `iam:PassedToService=ecs.amazonaws.com` 收紧。

## 已完成（Part 2）
- **数据持久化 ✅**：JSON 档 → **RDS Postgres**（users/scenarios/games），重部署/多实例数据一致；Fargate 临时文件系统不再存数据。
- **auth 登录 ✅**：注册/登录 + JWT（Bearer）取代共享 `APP_PASSWORD`；剧本 private/published、游戏永远私人、admin 看全部；空库首启 seed 初始 admin。

## 已知不足 / 下一步（可选硬化）
- **RDS 凭证轮换**：密码现明文在 GitHub secret + task definition。要硬化可改用 RDS IAM 认证或 Secrets Manager（目前刻意不上，保留灵活）。
- **DB 连接 TLS**：`DATABASE_URL` 未强制 `sslmode=require`；RDS 在私有子网，威胁面小，但生产应加。
- **JWT 仅访问令牌**：无刷新令牌/吊销名单，7 天到期即重登。
- **迁移并发**：多任务扩容时启动迁移会竞争，需改一次性迁移 task 或加 advisory lock。
