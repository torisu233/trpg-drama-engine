# 多 Agent 跑团式交互游戏 — 设计文档

## 一、概述

打造一个类似跑团（TRPG）的交互游戏。由多个 AI agent 分别扮演不同角色（队友、敌人），真人玩家扮演一个角色加入我方，与队友协作对抗敌人，进行多轮交互。交互不限于战斗——对话、谈判、战斗等皆走同一套循环。整体体感应接近「一本正在被共同书写的小说」。

系统的四个内核要素：

1. **行动意图** — 每个角色（含玩家）表达「这一拍想做什么」。
2. **意图裁决** — 一个中立机制裁决意图是否实现、实现到什么程度，并决定「谁察觉到了这件事」。
3. **交互结果描述** — 每次交互的结果被写成贴着视角的散文回馈给对应对象。
4. **行动次序流** — 用「行动条」推进节奏，把上述三件事串起来。

## 二、设计取向（内核前提）

本项目明确选择 **「气氛优先、快速原型、不追求机制公平」** 的路线。

传统跑团用骰子与数值制造「逆境与不确定」，本项目刻意**不靠骰子与血量数据决定成败**，而用**戏剧引擎**取代**几率引擎**——靠对抗、靠戏剧张力制造紧张与意外。

更进一步：本作不依赖数值来仿真局势，而是以**状态与情景**作为骨架。「一个被绑起来的敌人无法战斗」「一个喝醉的敌人更难命中」「一个背靠墙的敌人无法被背后偷袭」——这些用数值仿真很笨重，但对 LLM 而言是自然的推理。因此局势的骨架是一份**离散的状态事实清单（状态帐本）**，由裁决 agent 仔细推理、据以裁决。

对应的替代引擎：

- 一个真正难缠的**敌人 agent**，作为不确定性的来源
- 用「**结果阶梯**」取代命中判定
- 追踪质性的「**状态帐本**」而非血量数值
- 一点**运气神谕**作为调味（见第九节）

> 数值只出现在一个地方：**行动条的调度**（决定谁先动）。它是「调度数字」，从不决定成败，因此不违背上述哲学。

## 三、角色与 Agent 分工

设计刻意把职责分权，避免任何单一 agent 同时掌握「知道一切」与「裁决一切」的权力。

| 角色 | 由谁担任 | 职责 | 看得到的信息 |
|------|---------|------|------------|
| 敌人 | 独立的持久 LLM 对话 | 扮演狡猾、难缠的对手，尽力威胁我方 | 只看得到敌方当下**能感知**的局面（动态迷雾） |
| 队友 | 独立的持久 LLM 对话 | 与玩家同阵营协作，共享阵营计策 | 我方公开信息 + 阵营私有计策 |
| 玩家 | 真人 | 透过输入扮演我方一个角色，可用隐蔽手段传意图 | 我方信息 + 自己感知到的局面 |
| GM／叙事者 | 中立 LLM（与角色分开） | 把裁决结果写成贴着视角的散文，**逐对象分发不同版本** | 拿到「地面真相」与感知分发表作为输入，不偏袒任一方 |
| 流程控制器＋裁决器 | 程序 + 中立裁决 agent | 推进行动条、裁决意图、维护权威状态、决定谁知道什么 | 全知，但只运行规则、不带立场 |

设计重点：

- **敌人是独立 agent，而非由 GM 一手包办。** 理由不是公平，而是对抗品质——一个试图把全场做圆的 GM 会不自觉手下留情；一个只被告知「你要赢、你要威胁对方」的敌人 agent，才会给出真正让玩家难受的招。
- **角色 LLM 维持持久对话**（而非每拍重生的临时 subagent），以累积这场仗的记忆。
- **排序权、扮演权、裁决权三权分立**：决定顺序与裁决结果的必须是中立方，不能兼任任一角色。
- **角色 agent 永远不能直接改状态帐本**，只能「表达意图」或「放弃行动」。唯一能写帐本的是裁决 agent。

## 四、编剧层：剧本生成

**阶段一・编剧（脱机，迭代式）**：你给粗胚（例如「在酒馆和队友遇到敌人」），编剧 agent 把它展开成可被裁决的结构，并**埋好玩家不知道的秘密**（戏剧张力的来源）。流程为 **AI 提案 → 你可改任一栏 → 定稿**。

剧本内容（要点是「初始状态帐本 + 秘密 + 迷雾边界」，而非单纯场景描述）：

```
剧本 = {
  场景       : "雨夜酒馆，炉火将熄，后门通向马厩",
  角色卡     : [ …见第五节第一层… ],
  初始会变层 : { …见第五节第二层… },        // 姿势/位置/物品/秘密的起始值
  迷雾与秘密 : {
     "刀疤怕火"           : 可见性 gm,        // 玩家/队友不知道
     "刀疤在等同伙包抄"   : 可见性 gm
  },
  软目标     : "活着问出刀疤的雇主是谁"      // 可选；见第十二节「结束」
}
```

### 实作：编剧 agent（对话式区块编辑，共享剧本文档）

剧本＝可串行化的 `Scenario`（世界观＋scene＋角色卡＋初始会变层，存 `scenarios/*.json`）。两种编辑途径共用**同一份剧本正本**：

- **手动**：直接编辑各区块（前端表单）。
- **对话**：`author_turn(当前剧本, 对话史, 用户消息) → AuthorReply`——agent **对剧本无状态**，每回合收到当前完整剧本、**只更新一个区块**（world / scene / char / ledger / none）＋一句回复；程序把区块**以「空栏＝不更动」逐栏合并**回正本（ledger 角色用 key 级合并），**防 agent 误清既有内容**。

「无状态＋共享正本」＝前端持有草稿、agent 永远看到最新（含用户手动改的），存盘才落地。agent 内置编剧守则：双用角色卡、**弱点设 gm 秘密**、世界观法则影响裁决、埋钩子、设先机（初始行动值）、**阵营只用「我方/敌」**、能力弱点用质性描述。

**删除分工（刻意）**：因「空栏＝不更动」，agent 能做**改值/添加/栏内删一项**（回传变短的非空清单）；但**整张角色卡删除、整栏清空**留给用户在面板手动完成——破坏性操作手动更明确，也避免 agent 误删。

接口：前端编剧页（左可编辑面板＋右对话框）走 `POST /api/author/turn`，同一套无状态内核。

## 五、状态模型：世界观（静态）＋ 两层帐本

治理「状态很多」的内核手法是**把「几乎不变的」与「每拍会变的」彻底分开**，只有后者进入每拍重注入 + delta 的循环；并把会变层**按主体分组成嵌套视图**，让 agent 低负担取用。

「不变的」其实有两块：**世界观**（全局）与**角色卡**（个体）——两者都是裁决的静态依据，每拍重注入但不进 delta。

### 静态・世界观（全局法则，存剧本）

不只是氛围文字，更含**影响裁决的硬规则**：

```
世界观 = {
  基调 : "武侠。江湖恩怨、刀光剑影",                // 给 GM 语气
  背景 : "漕帮把持运河…约 200 字设置",             // 给所有 agent 接地
  法则 : [                                         // ★ 裁决必须遵守的硬规则
    "武功大成者运气护体，寻常刀剑难伤要害，须以内力/毒/火/点穴/攻其弱点/断其根基方能制之",
    "轻功高者可飞檐走壁、瞬间欺近或脱身",
    "内伤重于外伤，且难以速愈"
  ]
}
```
- `基调`→GM 语气；`背景`→所有 agent 接地；**`法则`→注入裁决，作为可行性的硬约束**（例如对护体高手用寻常刀剑，判为无效或大打折扣）。

### 静态・角色卡（个体，存剧本，极少改）

**双用字段**：一半给角色 agent 演戏，一半给裁决判定。**关键：角色卡不会被注入给对手**，因此「裁决用」的固有特质（防御/弱点）天然只有「裁决＋本人」知道，是**可被游戏中发现利用的秘密**：

```
char_scar = {
  名:"刀疤", 阵营:"敌",
  性别:"男",                                        // ★ 可观察的基本信息（性别/外貌/年龄）→ 列入视图与名册，公开可见，避免被脑补弄错
  ── 演戏用（角色 agent 与本人读；对手看不到）──
  身分背景 : "漕帮打手…",
  性格     : ["狡猾","记仇","欺软怕硬"],
  说话风格 : "皮笑肉不笑、爱抛狠话又留余地",        // 让对话有辨识度
  动机目标 : "拖到同伙包抄再一举拿下",              // 驱动其选择
  行为偏好 : ["能拖就拖","占上风才动手"],           // 惯用手段
  ── 裁决用（裁决全见；对手看不到，可为秘密）──
  能力     : ["漕帮快刀，近身狠辣"],
  防御特性 : ["横练护体，寻常拳脚难伤"],            // 影响裁决：难伤
  弱点     : ["怕火（秘密）","贪功怕死"]            // 影响裁决：攻其弱点效果显著
}
```
> 「固有特质放卡里 → 裁决全见、本人自知、对手看不到」——所以「怕火」这类秘密弱点能被玩家在游戏中发现并利用，而非开局摊牌。**已取得/外显**的状态（如当场被断一臂）才放会变层。

### 第二层・会变层（物品 + 各种状态，唯一由裁决 delta 修改）

按主体分组。每个角色一个整洁区块；另有场景区块与阵营私有区块：

```
会变层 = {
  角色: {
    char_scar: {
      姿势位置 : "背靠吧台站立",
      身心状况 : ["右肋重伤", "起疑"],          // 含会改变行为的心理状态
      特殊情况 : [],                            // 被绑/被囚/昏迷等高影响状态
      物品     : { item_knife: {状态:"完好", 位置:"右手"} },
      ── 衍生字段（裁决顺手更新，供程序/agent 直接使用）──
      行动速度 : "慢",                          // 由负伤推导 → 喂行动条
      感知能力 : "受限：分心，背后易疏忽"        // 由重伤推导 → 喂感知分发
    },
    char_player: { … }
  },
  场景: {
    空间关系 : ["刀疤背靠吧台 → 防背后偷袭、退路受限"],   // 关系/位置事实
    场景事实 : ["后门上锁", "炉火将熄"],                  // 环境 + 已揭露情报（用可见性控制谁知道）
    社会事实 : ["刀疤答应谈判期间不动手 → 毁约有代价"]     // ★ 承诺/协议/结盟/招供，带 gates 与可见性
  },
  阵营私有: {
    我方: { 计策: ["阿青引开、玩家绕后"] }       // 分发给敌人时整块滤掉
  }
}
```

**单一状态条目的通用结构：**

```
状态条目 = {
  内容    : 自然语言事实,
  gates   : "这如何约束后续行动",   // 裁决「创建时」写好，之后优先读它（缓存推理、防漂移）
  程度    : 可选，只在会恶化时给质性阶（微醺/醉/烂醉、轻伤/重伤/濒死）,
  可见性  : public | faction:阵营 | self:角色id | gm,
  来源    : 哪一拍哪个行动造成,
  生命周期: 何时失效/解除,
  剩余拍数: None=持久；整数=N 拍后自动过期（瞬态，见第五节末「长场景维护」）
}
```

**物品**置于会变层（可消耗、可破损），但保留「身分稳定 / 状态可变」拆分以防名称漂移：

```
item_knife = {
  ── 稳定 ── 名:"生锈短刀", 类型:"武器", 固有性质:["刃钝","易断"],
  ── 可变 ── 状态:"完好→缺口→折断", 位置:"右手→落地", 数量:(消耗品才有)
}
```

### 低负担三原则

1. **嵌套分组**：agent 不读全域大清单，只读「它能感知到的、已整理好的视图」。
2. **衍生字段缓存**：`行动速度`、`感知能力` 由裁决顺手算好，行动条循环与感知分发直接取用，不必每次重推。
3. **稳定栏 vs 可变栏分明**：裁决只准动可变栏；设置与固有性质永不被误改。

### 社会/信息事实的归属（多轮对话的记忆关键）

帐本即长期记忆——**帐本是全量注入、不截断的**（叙事散文流才用滑动窗）。所以「该记住的事」要进帐本，而非只留在会被截断的散文里。对话/谈判产出的东西分三类归属：

- **承诺/协议/结盟/停火/招供 → 添加 `社会事实` 栏**（场景层），带 `gates`（毁约/破坏的后果）与可见性。
- **已揭露情报（谁知道了什么）→ 复用 `场景事实` + 可见性**，不另设字段（可见性本来就 = 谁知道）。
- **对人态度（起疑/动摇/信任）→ 留在 `身心状况`**（它就是心理状态），不另设字段避免膨胀。

这样 10 轮对话后，第 1 轮的招供/承诺仍在帐本里有效，且 fog 由可见性自动正确。

### 长场景维护：滚动摘要（文气）＋ 瞬态 TTL（清理）

两个「每拍结束」的自动维护步骤，让场景拉长也不爆 context、不堆积：

- **滚动摘要（管文气）**：角色记忆 = `摘要（压缩的旧事）＋ 最近 W 拍逐字`（W=5）。某角色记忆达 2W=10 条时，把最旧 W 条交摘要器**合并重压**进滚动摘要（per-character，迷雾忠实）。摘要**只记故事感/关系/情绪/张力，不记精确状态**（状态在帐本）。只摘要 AI 角色（玩家是真人、自读公开日志）。
- **瞬态 TTL（管清理）**：`剩余拍数`（None=持久；整数=N 拍后消失）。裁决为短暂状态（姿势晃动/被惊吓/火光蔓延）设 1–3 拍，持久状态（伤势/承诺/情绪转变）留 null；程序每拍按 `回合数 − 创建回合 ≥ 剩余拍数` 自动修剪。
- **重复累积的根治（已实作「帐本整理 pass」）**：TTL 只清「过期瞬态」；「升级不删旧」造成的近义重复（同一条招供被反复添加）由**帐本整理 pass** 根治：每拍结束后，若某清单的「**公开且持久**」条目达门槛（预设 4），调用 LLM 合并近义、清冗余；**gm／self／faction／带 TTL 的瞬态一律不动**（保护迷雾与 TTL）。自我调节——合并后缩短，再累积到门槛才触发。裁决纪律（升级即删旧）作为辅助。

## 六、行动次序流：行动条

取代死板的轮流。每个角色有一条行动条，按「行动速度」累积；达到**门槛（20）**即可行动，行动后**扣掉门槛、保留溢出**（公平且平滑）。速度由**当下状态实时推导**，反映虚构。

```
loop:
  各角色 += 行动速度                          // 每发生一次行动，全场累积一次
  while 没人达门槛:  各角色 += 行动速度        // 没人能动就再加，直到有人达标
  actor = 达门槛者中行动值最高者
          （平手：玩家优先 → 否则值高者 → 再否则固定序 快>常>慢）
  actor 行动（玩家→暂停等输入；NPC→agent 出意图）
  → 两轴判定 → 裁决 → 叙事 → 分发
  actor.行动值 -= 门槛                         // 保留溢出，不归零
```

> **为何保留溢出、不归零**：只要每次扣门槛保留溢出，长期下来「行动次数比 = 速度比」，比例干净可预测；归零会丢失溢出、扭曲比例。这条是整个机制公平的关键。

速度值（基础收紧在 4–7，避免次序拉太开；极端状态才破格往下）：

| 当前状态 | 速度 | 长期行动占比 | 相对玩家 |
|---|---|---|---|
| 玩家（预设略高） | 7 | 32% | 1.0× |
| 快（灵活戒备） | 6 | 27% | 0.86× |
| 常（普通） | 5 | 23% | 0.71× |
| 慢（负伤／酒醉／笨重） | 4 | 18% | 0.57× |
| 重伤 | 3 | — | 破格 |
| 濒死／被压制 | 2 | — | 破格 |
| 昏迷／重缚 | ≈0 | — | 自然排不进来 |

设计效果：

- **次序不拉太开**：正常区间 4–7，最慢者仍有玩家 57% 的出手率，没人被晾在一边；玩家又明显最活跃。
- **重度状态才真的拖慢**：日常变化收紧，但重伤/濒死破格往下，受创确实降低节奏。
- **昏迷者速度≈0，行动条永不满，自然轮不到他**——以结构取代「强制跳过」。万一仍排到，agent 也清楚自己昏着，演成「动弹不得」。**不设硬性跳过旗标，让 agent 自行理解状态。**
- **速度随虚构实时变化**：速度从会变层的 `行动速度` 衍生栏读取，一旦被打成重伤，下一个 tick 就立刻变慢。行动经济自动跟着局势走。
- **先机由初始值播种**：全员从 0 起跳则玩家必先手；要做突袭/埋伏，让剧本把偷袭者的初始行动值设高（例如起手 15），即可让敌人抢到开场。先机用「初始值」表达，不去动基础速度。
- **可选旋钮**：行动「成本」可变——拚命的重击扣较多值（下次更晚轮到），轻巧动作扣较少。给战术质感，仍不碰成败数值。

## 七、裁决 agent：行为与知识的中枢

裁决 agent 是整个系统的权威内核，肩负**两项并重的职责**：

- **行为管理**：判断意图在当前状态下是否可行、实现到何种程度，并把结果写成对状态帐本的增删改（delta）。
- **知识管理**：决定这件事**谁察觉到、察觉到多少**，产出一张感知分发表，据此维持并动态调整迷雾。

两者都必须中立、可审计，因此用 **structured output 逼出一条可检查的推理链**，避免它偷懒、漏看状态、或被角色的话术说服（例如敌人 agent 在意图里夹带「我早就挣脱了绳子」——裁决必须以帐本为唯一真相来源，驳回未经裁决的既成事实）。

### 强制思考协议（裁决的双输出）

```
裁决输入：本拍行动意图（+ 对方反应意图，若有收集）
        + 世界观法则 + 完整状态帐本（地面真相，含各角色固有特质：能力/防御/弱点）
        + 运气神谕结果（若为争议）

裁决输出（强制格式）：

A. 行为裁决
  1. relevant_conditions : ["char_scar.特殊情况: 双手被反绑", "场景.空间关系: 背靠吧台"]
        └ 逼它列出它「看到」哪些相关状态，不准无视
  2. per_condition_judgment :
        双手被反绑 → "阻止"（无法持械攻击）
        背靠吧台   → "改写"（背后无空间可绕）
  3. feasibility   : 不可能 / 受阻 / 可行 / 需改写
  4. ladder_choice : 成功 / 成功但有代价 / 局势逆转   （结果阶梯，见第九节）
  5. ledger_delta  : { add:[…], remove:[…], modify:[…] }   // 唯一的权威状态变更

B. 知识裁决
  6. 感知分发 : {
        char_scar(重伤分心) : "未察觉",                 // 注意不到背后动作
        char_boss           : "察觉：看到玩家移动",
        ally_阿青(队友)     : "察觉＋懂暗号真意"
     }

C. 给 GM 的地面真相摘要（一句话）
```

这套协议达成：

- **第 1、2 步逼它看完所有相关状态、世界观法则与角色固有特质**——不准无视「被绑」就判攻击成功，也不准无视「护体难伤」「怕火」这类法则/特质（对护体者用寻常刀剑须判无效或大打折扣；攻中弱点则效果显著）。
- **第 5 步让状态变更显式化**：局势只能透过 delta 改变，不能在散文里偷偷漂移。对话/谈判的持久后果（招供/承诺/结盟/情报）也由 `ledger_delta` 记为「社会事实」，不只记物理状态。
- **第 6 步把「谁知道什么」收归裁决**：唯有看得到全场状态的裁决，才有资格判断感知。迷雾因此能随重伤、蒙眼、昏迷动态收窄。
- **整条链可被程序或一个轻量检查审计**：若它判「攻击成功」却没在第 2 步处理「被绑」，即为漏判。

## 八、行动的两轴判定：反应与争议

一个行动进入裁决前，程序先沿**两条独立的轴**做判定。两轴常同时成立，但**不是同一件事**，务必分开处理：

| 轴 | 问题 | 决定什么 |
|---|---|---|
| **A. 要不要收集反应？** | 对方需要先做出反应，再交裁决吗？ | 是否多收一次「反应意图」 |
| **B. 是不是争议行为？** | 结果真的不确定吗？ | 是否掷运气神谕 |

对照：攻击清醒的敌人＝两者皆是；无人阻挡的后撤＝两者皆否；被紧逼时后撤＝不收反应、但是争议。

### 轴 A：对方要不要先反应？

**内核原则：只有当「结果取决于某个防御者『当下、且他感知得到』的选择」时，才收集反应。** 过三道闸门：

1. **对方感知得到吗？** — 感知不到就无法反应。背后偷袭一个没注意到你的敌人 → 不收反应，裁决直接当「突袭」处理。（呼应第十节：**你只能反应你察觉到的事**。）
2. **对方有能力做有意义的对抗吗？** — 被绑、昏迷、失能者 → 无从反应，裁决直接判。
3. **对方是玩家吗？** — 是的话**一定**给玩家反应。这就是「每一拍收在威胁上」的命脉：敌人攻过来 → 玩家必须回应，这一拍的钩子自然成形。

> **时序与「宁可多收」**：反应在裁决*之前*收集，但「对方究竟感知到没」要到裁决*之中*才定案。程序预判时用 `感知能力` 衍生栏粗筛，**模棱两可一律收**；裁决事后若认定其实没察觉，再把该反应裁定为无效。宁可多收、不可漏收。

**关键限制：反应是「意图」，不是「判决」。** 防御者可以表达「我要闪避」「我嘴上答应、心里盘算反咬」，但**不能自行声明成败**。裁决拿 `行动意图 × 反应意图 × 状态 × 运气` 一起判，并参考防御者的状态与攻方手上的筹码（例如握有把柄＝帐本里一条状态）才决定结果。否则被说服的敌人一句「我不为所动」就破功了。

> **反应是一种中断（interrupt）**：防御者为了防御而反应，**不消耗他自己行动条的主动回合**（可选旋钮：拚命的翻滚闪避才扣一点条）。所以「敌人出手 → 玩家被迫回应」不会打乱行动条经济，反而是它的心跳。

### 轴 B：什么是争议行为？

- **非争议（不掷运气，直接裁决）**——结果由状态预先决定：
  - 明显可行：无人阻挡的后撤、捡起脚边的刀。
  - 明显不可能：被绑者挥拳、对昏迷者说服。
- **争议（掷运气神谕）**——结果真正不确定，通常因为：
  - (a) 对方能感知且能主动对抗（攻击、说服清醒的敌人）；或
  - (b) **环境本身是赌注**（雨夜跳过屋顶裂缝、压力下开锁）——这类**没有对手，但仍是争议**。

### 走一遍范例

- **① 攻击清醒的敌人**：轴 A 是（感知✓、能对抗✓）→ 收反应；轴 B 是 → 掷运气。裁决判 `攻击 × 防御` 冲突。
- **② 说服敌人**：轴 A 是 → 收反应（但反应是「抗拒/动摇/假意顺从」的*立场*，非判决）；轴 B 通常是。裁决看敌人的多疑/恐惧 + 攻方筹码，常判「成功但有代价」。
- **③ 打斗时后撤几步**（两种情况）：
  - **无人紧逼**：轴 A 否、轴 B 否 → 不收反应、不掷运气，裁决只轻量更新 `姿势位置`，一句带过。
  - **被敌人紧逼**：轴 A **否**（后撤不针对敌人，敌人「要不要追」是他*自己回合*的主动决定），轴 B **是**（环境争议，掷运气）。裁决用结果阶梯判代价：「成功但有代价」（拉开距离但露空档被划一刀）或「局势逆转」（被顺势逼向墙角）。

> 为何后撤*不*收敌人反应、而攻击*要*？攻击的结果**直接取决于**防御者当下的闪/挡选择；后撤的结果取决于**环境态势**（相对位置、是否被紧逼），那是裁决读帐本就能判的。敌人的「追击」留到他行动条轮到时再主动做。

### 单拍两轴流程

```
行动者意图（攻击/说服/后撤…）
   │
   ▼
[程序] 轴 A：对方该反应吗？（感知✓ 能对抗✓ 或 是玩家）
        是 → 收集对方反应意图（玩家则暂停等输入）
        否 → 跳过（突袭 / 对失能者 / 无对象行动）
   │
   ▼
[程序] 轴 B：争议行为吗？  是 → 掷运气神谕（隐藏）
   │
   ▼
[裁决] 判「行动意图 ×（反应意图）× 状态 × 运气」→ 结果阶梯
        → ledger_delta ＋ 感知分发表
   │
   ▼
[GM] 逐对象叙事 → 分发
```

## 九、取代骰子的机制细节

### 1. 行动意图

- 所有角色每拍只输出**决策**，用结构化格式表达。原型采**三栏精简**：`{ 行动:"掀翻桌子撞向刀疤", 目标:"刀疤", 隐蔽:false }`。
  - `行动`：一句话描述「想做什么（**含具体做法**）」。原本设想拆成「行动类型 + 方式」两栏，但实作发现玩家容易把两栏写成重复，且 LLM 看一句完整描述就懂——故合并为单栏；做法细节（攻哪里/用什么/利用环境/时机）直接写在这句里，才是改变裁决的关键。
  - `目标`：**主要对象**（char_id 或留空）——程序据此判轴 A 向谁收反应。它是「主要对象」，不是「唯一交互对象」。
  - `隐蔽`：是否想**瞒过敌人**（信息维度，与「成不成功」的争议维度无关）；true 时裁决做表象/真意拆分并判是否被识破。潜行/暗号/偷偷拔刀属此。
- **有限复合**：一拍可含「一个主要动作 + 一个附带小动作」（攻击同时打暗号、后撤同时嘲讽），写进同一句 `行动`。
  裁决逐部分判、权衡一心二用的代价（成功但有代价）；附带对象（如收暗号的队友）由感知分发处理、不另收反应。别贪多，一两件即可。
- 意图只说「想做什么」，**绝不自行声明成败**。扮演敌人的 LLM 不可以说「我砍中了」——裁决权不在角色手上。

### 2. 结果阶梯（取代命中判定）

裁决时不掷骰，而是从阶梯挑一个**最有戏、且在已创建虚构里最合理**的结果：

- **成功**
- **成功但有代价**
- **局势逆转**

挑选依据是戏剧性与合理性。关键原则：**很少给干净的成功**——多数动作回馈的是「你做到了，但……」，那个「但」就是让场面继续滚动的燃料。每个结果都以 `ledger_delta` 落地。

### 3. 叙事原则（写进 GM 的 system prompt）

- **后果是质的、会改变能力的**：不写「掉几滴血」，而写「右臂中刀后只能用左手」「武器断了」。每个结果改写下一步能做什么。
- **每一拍收在威胁或选择上**：保持「对打」而非「独白」的命脉。
- **时间弹性**：无聊对峙一句带过，关键一击拆成慢动作；火力集中在那一个转折点。
- **充分而不杜撰（丰富度）**：叙事者除一句 GM 摘要外，还拿到裁决的**相关状态/逐条判定**与**登场者性格口吻**，据此把有戏的关键拍铺陈成饱满一段（神态、动作、实际对白、情绪），长度随份量；但所有细节**必须源自这些既有事实**，不得发明。角色意图也可有层次（含实际对白与神态）。
- **贴着视角写**：写角色的恐惧、判断、痛感。
- **逐对象分发**：依感知分发表，给每个收件者写各自版本的私密叙事。
- **准确归属**：严格按「行动者/对方回应/状态变更」写谁做了什么、谁被影响，不可张冠李戴或改写事件性质（如把「某人计谋被识破」写成「某人无处藏身」）。
- **只写本拍新发展**：叙事者会拿到「最近 1–2 拍的公开叙事」当故事进展——**承接它但不可复述**已写过的事件或对白；本拍若只是继续僵持，只写这拍添加的细节。这是叙事品质的命脉（玩家看最多的就是叙事）。

### 4. 状态帐本即局势（取代血量）

第五节的会变层就是局势的权威记录。每次裁决更新它，并让后续动作**受其约束**（受伤的手臂使不出重击、背靠墙的人退无可退）。

### 5. 运气神谕（每个争议行动都掷）

在**争议行动**（见第八节轴 B）上，程序掷一次粗的质性运气（`霉运 / 平 / 好运`），作为**喂给裁决 agent 的偏置文字**，不是命中率：

- `霉运` → 裁决把结果阶梯下调一阶、或编一个倒楣的并发状况（「刀在洒出的酒上打滑」）。
- `好运` → 容许罕见的干净成功，或一个意外的有利转折。
- **怎么倒楣／走运，由裁决在虚构里决定**，保持剧情合理。
- 运气**对角色 agent 隐藏**，只有裁决看得到，否则敌人 agent 会偷算。

非争议的行动不掷，直接裁决。

## 十、知识与迷雾模型

**前提：单一场景、所有人同场行动。** 因此大多数物理动作是**全场可见（public）**，迷雾不是骨架而是例外。私密信息只有三个来源：

1. **剧本预先准备的秘密**（`gm` 可见性）：弱点、隐藏意图、暗藏物品——开场就藏好，靠剧情揭露。
2. **剧本指定单一阵营可发现**：避免每次都得为每个阵营裁决「谁发现了」；预设归属一个阵营。
3. **暗号（表象/真意）**：表象全场可见，但只有同阵营懂真意；别人看到了也不知道意思。

在这之上再叠一层**动态感知修正**（次要、例外）：蒙眼、昏迷、重伤分心的人，可能连全场公开的动作都漏看。

### 1. 表象与真意（由裁决拆分）

例如玩家桌下打手势通知队友——敌人看得到手动了（表象），但不懂意思（真意）：

```
玩家行动：桌下打手势
  表象 : "玩家手指在桌沿动了动"      // 全场可见
  真意 : "示意阿青绕到刀疤背后"      // 只有我方懂
```

**角色 agent 只提供「意图 + 想隐蔽的标记」；真正拆成表象/真意、并判定隐蔽是否成功，是裁决的知识管理职责。** 推论：**隐蔽可能失败**——眼尖的刀疤可能读穿你的手势，这由裁决判定，不是自动成功。

### 2. 动态感知修正（例外层）

- 昏迷 → 什么都收不到。
- 蒙眼 → 无视觉、有听觉。
- 重伤分心 → 可能漏看别人的小动作。

接收者「收到什么」由其 `感知能力` 衍生栏决定，裁决在感知分发表里逐人判定（全部 / 部分 / 无）。这也直接决定第八节轴 A：**感知不到的人无法反应**。

### 3. 阵营私有与隐蔽协同

- 阵营计策是一条 `可见性 = faction:我方` 的状态，多为剧本预设或私下商议产生；分发给敌人时整块滤掉（敌人或许看到我方在低声交谈，但不知内容）。
- **「私下商议」动作**：玩家与队友在敌人「不知内容」的信道对话，谈定的计划写成 faction 计策。商议**不推进行动条**，产物由裁决 commit 进帐本。
- 队友与玩家的信息边界：队友看得到玩家的公开行动与阵营计策，但玩家的内心盘算未必喂给队友 agent。

## 十一、角色职责契约与信息边界

把各角色的「做什么 / 知道什么 / 完成什么」钉成实作契约：

| 角色 | 做什么 | 知道什么 | 完成什么（产物） |
|---|---|---|---|
| 编剧 agent（脱机） | 展开剧本、补全状态、埋秘密、设初值 | 玩家粗胚 + 常识（全知造物） | 剧本档：**世界观（基调/背景/法则）**＋**双用角色卡[]**（演戏栏＋裁决特质）＋初始会变层（含衍生栏、初始行动值、社会事实）＋迷雾秘密＋软目标 |
| 流程控制器（程序，非 LLM） | 推行动条、两轴预判、掷运气、迷雾过滤分发、暂停等玩家、套用 delta、判结束、主持私下商议 | 全知，但只运行规则、不裁决 | 行动者、运气值、各方视图、暂停点、更新后帐本 |
| 角色 agent（敌/友） | 出行动意图/反应意图、可放弃、可发隐蔽意图、私下商议 | 只有「感知分发允许＋自己记忆」；我方多看阵营计策 | 结构化意图/反应，**绝不声明成败** |
| 裁决 agent | 行为裁决＋知识裁决、更新衍生栏、出 GM 摘要 | 完整地面真相＋意图（＋反应）＋运气 | 双输出：ledger_delta＋感知分发表＋GM 摘要 |
| GM／叙事 agent | 逐对象写贴视角散文、收在威胁上、准确归属、只写本拍新发展 | GM摘要＋感知分发表＋本拍行动者/回应/状态变更＋最近叙事(故事进展)＋公开场面锚点 | 1 份公开叙事＋N 份私密叙事 |

### 已定案的六条边界规则

1. **反应宁可多收**：轴 A 模棱两可时一律收反应；裁决事后可裁定无效。宁可多收、不可漏收。
2. **表象/真意由裁决决定**：角色只标「想隐蔽」，裁决负责拆分并判定隐蔽是否成功（**可能被识破**）。
3. **初值由编剧设**：`行动速度`/`感知能力` 衍生栏与初始行动值，皆由剧本给定；之后由裁决维护、程序只读缓存。
4. **私密信息的来源（单一场景前提）**：剧本预设秘密（`gm`）／剧本指定单一阵营可发现／暗号（看得到表象、不懂真意）／**角色卡固有特质（裁决＋本人知，对手看不到，可在游戏中被发现利用）**。运行时极少动态裁决「谁发现」。
5. **GM 写、程序送**：GM 只负责写各版本散文，**由程序按感知分发路由进对应记忆**；维持迷雾边界永远是程序的责任。
6. **帐本永远胜出**：角色记忆与权威帐本冲突时，以**裁决写好的帐本**为准；每拍重注入该 agent 可见视图即自动矫正漂移。

## 十二、轮次流程总图

```
[编剧层] 编剧 agent ── 脱机迭代产出剧本（初始帐本 + 秘密 + 迷雾）
        │
────────  以下实时循环，由行动条推进  ────────
        ▼
[程序] 行动条累积 → 选出本拍行动者（玩家优先）
        │
        ▼
[角色 LLM / 玩家] 产出行动意图（只说想做什么，可复合，可隐蔽）
        │
        ▼
[程序] 两轴判定：
        轴 A 该收反应？ → 是则收集对方反应意图（玩家则暂停等输入）
        轴 B 是争议？   → 是则掷运气神谕（隐藏）
        │
        ▼
[裁决 agent] 强制思考协议：
        行为裁决（结果阶梯 + ledger_delta）
        ＋ 知识裁决（感知分发表）        ← 行为与知识并重
        │
        ▼
[GM/叙事 LLM] 依感知分发，逐对象写散文（收在威胁上）
        │
        ▼
[程序] 公开叙事给全体 / 私密结果回灌对应对话记忆（维持动态迷雾）
        │
        └──────→ 行动者行动条归位，回到行动条累积
```

**「结束」如何判定**（小说式流程没有 HP=0 的硬结局）：

- 剧本软目标达成（问出雇主、活着离开）；或
- 玩家主动喊停；或
- 场面张力彻底消解、无未解威胁可继续。

## 十三、实作备注

- **模式中立（prompt 不偏战斗）**：裁决/叙事/角色 agent 的 prompt 不写死「威胁压制」这类战斗指令；角色依**自己的动机目标**行事、手段随情境。对话/交涉、伪装/潜入皆走同一套（状态＋结果阶梯＋社会事实＋隐蔽感知），用该模式合适的**质性后果**——交涉记信任/让步/把柄（社会事实）、潜入靠是否被识破（隐蔽感知），战斗才写伤势。叙事「收在未决张力上」（威胁/疑点/抉择皆可，不限威胁）。
- **角色记忆**：敌人、队友各自维护一条持久对话历史，每拍往后接，记忆自然累积。迷雾边界由程序划定——分发局面时只给该方「感知分发表所允许」的信息。
- **结构化一切**：意图、反应意图、裁决输出（行为 delta + 感知分发）、状态条目，全用 structured output 固定格式，方便程序解析与审计。
- **规则与裁决尽量写在程序里**（两轴预判、合法性检查、行动条推进、运气掷点、迷雾过滤），**仔细推理的部分交给裁决 agent**（结果阶梯选择、状态 delta、感知判定），**润色交给 GM**。
- **真人输入**：行动条每轮到玩家、或玩家被收集反应时，停下等输入。这是保留薄程序框架的主因（自主 agent 的本能是一路跑完，需要被框住）。
- **裁决成本**：每个争议拍可能涉及 行动意图 + 反应意图 + 裁决 + GM 多次 LLM 调用，是这条路线的固有代价。
- **复用 ai-word**：`ActionAnalyzer`（解析意图）、`ReactionJudge`（反应收集，对应第八节轴 A）、`NarrativeGenerator`、`BattleEngine`（流程协调）可大量复用；`CombatCalculator` 的数值计算整个换成「裁决 agent + 状态帐本」；`BattleState` 换成两层状态模型。添加的是持久角色 agent 对话与动态迷雾分发层。

## 十四、一句话总结

把「骰子＋数值」这套**几率引擎**，换成「对抗 agent ＋ 结果阶梯 ＋ 状态帐本」这套**戏剧引擎**：
**程序管「顺序与框架」，裁决 agent 管「行为成败与谁知道什么」，角色 LLM 管「想做什么」，GM 管「逐人讲得好不好听」。**
